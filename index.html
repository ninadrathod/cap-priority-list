CAP Priority List

How the recommendation system works

A percentile-based matching engine that turns historical Maharashtra CAP cutoffs into a short, realistic college–branch preference list for one candidate.

Overview Inputs Pipeline Scoring Buckets Output Limits

Overview

The system does not invent college rankings from reputation. It rebuilds chance from published CAP closing percentiles, then compares those closings to the candidate’s MHT-CET percentile.

Higher percentile = stronger score. A historical closing of 88.5 means students typically needed about that percentile (or better) to get that seat.

1

Build a cutoff database

Parse 3 years × CAP rounds 1–3 PDFs into data/cutoffs_db.csv.

2

Read the scorecard

Extract name, category, total percentile, and gender (for Ladies seats).

3

Filter eligible seats & streams

Keep only category-relevant seats and user-selected branch streams.

4

Score, bucket, shortlist

Estimate chance, split into aspirational / moderate / safe, emit ~100 options as CSV (govt / aided preferred).

Inputs

Historical cutoffs

From raw/ → parsed by scripts/parse_cutoffs.py

  • Years: 2022–23, 2023–24, 2024–25
  • Rounds: CAP1, CAP2, CAP3
  • Fields: college, branch, choice code, category, merit rank, percentile, stage

Candidate scorecard

MHT-CET PCM scorecard PDF

  • Total percentile (primary signal)
  • Reservation category (e.g. DT/VJ, OBC, OPEN)
  • Gender → include L* seats only if female
  • Preferred streams (CS/IT, Electronics, Electrical, Mechanical, Civil)

Seat categories used

Reserved candidates are matched on their category codes (example: DT/VJ → GVJH / GVJO / GVJS) and OPEN seats (GOPEN*). Male candidates use G* only; female candidates also get L*.

Home University is not applied yet: H / O / S seats are pooled, and the easiest eligible closing in each year–round is used as the chance signal.

Pipeline in detail

1. Parse cutoffs into a central DB

Every cutoff PDF page is scanned for college headers, choice-code/branch headers, category rows, and Stage-I (plus II / VII / I-Non / MH minority) allotments. Codes are normalized (zero-padded; suffixes like F, K, U preserved).

Result: one flat table of historical closings used by all recommendations.

2. Restrict to selected branch streams

Each branch is classified into one of five streams:

# Stream Context
1Computer Science & ITSoftware, Data, AI, Computing
2Electronics & CommunicationSignals, Communication, Embedded, Instrumentation
3Electrical EngineeringPower Systems, Circuits, Energy
4Mechanical EngineeringMachines, Manufacturing, Industrial & Process
5Civil EngineeringInfrastructure, Structures, Built Environment

The CLI asks which streams to include (or accepts --streams 1,2 / cs,mechanical / all). Only matching branches enter the shortlist.

3. Build per college–branch observations

For each choice code, every year–round observation stores the best (lowest) closing percentile among eligible seats for that candidate. That is the easiest historically available path in that round.

cleared = candidate_percentile ≥ best_closing_percentile

Scoring & chance filter

Each option gets a competitiveness / difficulty score from weighted historical closings:

year weights: 2024–25 = 0.50, 2023–24 = 0.30, 2022–23 = 0.20
round weights: CAP1 = 1.00, CAP2 = 0.75, CAP3 = 0.55

difficulty = Σ (best_closing × year_w × round_w) / Σ (year_w × round_w)

Higher difficulty ≈ historically tougher closing ≈ more competitive option.

Keep only options with a real chance

  • Ignore one-off fluke dips unless reachable in ≥ ~25% of observations
  • Drop options whose easiest historical closing is still > candidate + 3 percentile points
  • Drop ultra-low “filler” safes far below the candidate (not useful as primary preferences)

Three recommendation buckets

Aspirational

Slim possibility. Closings usually sit above the candidate, but enough history is near enough that a late round / softer year could open a seat.

Moderate

Borderline-to-plausible. Candidate clears a meaningful share of past rounds, or sits close to the median closing band.

Safe

Strong historical clearance, especially on CAP1, with median closing clearly below the candidate’s percentile.

Within each bucket, government / government-aided / university colleges are preferred when they qualify; remaining slots fill from private colleges ordered harder → easier. so the CSV can be used almost directly as a CAP preference order. Multiple branches from the same college are allowed.

Output

Running generate_recommendations.py writes output/recommendations.csv with:

  • priority — overall preference order
  • bucket — aspirational / moderate / safe
  • stream — branch stream label
  • college, branch, choice_code, college_type
  • median_closing_percentile, min_closing_percentile
  • difficulty_score, clear_rate
  • candidate fields echoed for traceability
python generate_recommendations.py scorecards/scorecard.pdf \
  --streams 1,2 \
  -o output/recommendations.csv

What this system does not claim

Not a guarantee

Past closings are a guide. Seat matrices, applicant pools, and policy can shift year to year.

No Home University yet

H vs O cutoffs are pooled. Adding HU will tighten regional recommendations.

No reputation ranking

Ordering inside buckets is competitiveness of cutoffs, not NIRF / placement rank.

Merit number optional

Until state merit is out, matching is percentile-based from the CET scorecard.
