CAP Priority List

A Maharashtra CAP engineering preference recommender. Given an MHT-CET scorecard and historical CAP cutoffs, it builds a shortlist of college–branch options ranked into aspirational, moderate, and safe buckets.

Python CLI MHT-CET → CAP 3 years × CAP 1–3 ~100 preference rows
About Architecture How it works Layout Run Limits

About

CAP allotment is competitive and category-specific. This project does not invent college rankings from reputation. It reconstructs chance from published closing percentiles, compares them to the candidate’s MHT-CET percentile, and emits a curated CSV that can be used as a starting preference list.

Higher percentile = stronger score. A historical closing of 88.5 means students typically needed about that percentile (or better) to get that seat in that round.

Architecture

Two stages: a one-time (or rare) offline build of a cutoff database, then an online recommendation pass for each candidate scorecard.

How it works

  1. Parse the scorecard

    Extract category, total percentile, and gender. Gender controls whether Ladies (L*) seats are eligible; males use G* only.

  2. Build the eligible seat set

    Reserved candidates match their category codes (e.g. OBC → GOBCH/O/S) and OPEN (GOPEN*). Only Stage-I rows with a percentile are used. Home University is not applied yet — H / O / S seats are pooled and the easiest eligible closing per year–round is kept.

  3. Filter by branch streams

    User selects streams (interactive or --streams). Specialized branches outside the five streams are dropped.

  4. Score each college–branch (choice code)

    For every year–round observation, take the best (lowest) closing among eligible seats. Weight recent years and earlier CAP rounds more heavily:

    year: 2024–25 = 0.50 · 2023–24 = 0.30 · 2022–23 = 0.20 round: CAP1 = 1.00 · CAP2 = 0.75 · CAP3 = 0.55 difficulty = Σ (best_closing × year_w × round_w) / Σ (year_w × round_w)

    Options with no realistic chance (e.g. easiest closing still > candidate + 3) are discarded.

  5. Assign buckets

    Aspirational

    Slim chance — closings usually above the candidate, but history is near enough.

    Default 30

    Moderate

    Borderline — clears a meaningful share of past rounds, or sits near the median band.

    Default 40

    Safe

    Strong clearance, especially on CAP1, with median closing clearly below the candidate.

    Default 30

  6. Shortlist with ownership preference

    Within each bucket, fill Government → Government-Aided → University first, then private / un-aided colleges by difficulty. Multiple branches from the same college are allowed. Total default: 100 rows.

Inside a bucket, preferred ownership comes first; among peers of the same type, harder (higher difficulty) options rank higher so the CSV order is close to a usable CAP preference sequence.

Run

Requires Python 3 and pypdf.

pip install -r requirements.txt
python scripts/parse_cutoffs.py          # once, or after new raw PDFs

python generate_recommendations.py scorecards/scorecard.pdf \
  --streams all \
  -o output/recommendations.csv

Useful flags: --streams 1,2 / cs,mechanical, --aspirational / --moderate / --safe, --female / --male.

What it does not claim

Not a guarantee

Past closings guide chance. Applicant pools, seats, and rules change yearly.

No Home University yet

H vs O cutoffs are pooled. HU filtering would tighten regional results.

No reputation ranking

Order reflects cutoff competitiveness (and ownership preference), not NIRF or placements.

Percentile-first

Matching uses CET percentile from the scorecard until state merit is available.
